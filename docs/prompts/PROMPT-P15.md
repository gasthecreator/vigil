## Why this project exists (hold this while you work)
The owner's mother died of breast cancer in Abuja: lab results were dismissed, radiotherapy was scarce, and the family did not understand what was happening. Vigil exists so that a worrying trend is never silently dismissed, scarce treatment goes where delay hurts most, and families understand. A fabricated number, a UI-only safety gate or an overclaimed result can hurt exactly such a patient. Truth over impressiveness is the whole job.

## Ways this project has gone wrong — do not repeat (the owner requires this list in every prompt)
Strong models avoid the crude versions of these and fall into the quiet ones. Each was reproduced by the overseer in earlier rounds.
1. **Prose that outruns evidence.** Reports described studies that were not run (wrong grids, wrong seeds), results as "slightly" worse when they were 4–21× worse, "signed" manifests that were hash lists, "sustained" soaks of 5 seconds, "RPO 0" from a temp SQLite file. *Every sentence about a design or number is copied from the PREREG, script or result file; name exactly what was measured, how long, on what.*
2. **Result files edited or numbers typed.** Results are written by their script only; a CI job re-runs cheap studies and diffs them. To change a result, change the script and re-run.
3. **Tuning on evaluation data, and silent changes after PREREG.** Development seeds ≠ frozen evaluation seeds. Every change to a model, objective or primitive after PREREG is listed in the report with its reason (`git diff` pasted). PREREG is committed alone, before running.
4. **Validating a stand-in, or a pattern against itself.** A study of component X calls X. A generator and the detector it tests never share their definition of the signal. An input produced by the system under test cannot validate it.
5. **Safety enforced only where it is easy to see.** Safety gates, consent and authorization are server-side invariants tested over HTTP as every role, with forged bodies, on every sibling route that can return the data. Security properties are never tested by editing the database. Test hooks live in tests, not production classes. A new route without a policy-table entry must fail CI.
6. **Self-grading.** Audits that score by file presence; hazard logs with no open items; "MET" without an existing, passing test. An audit must be able to fail. Report the strongest baseline first and say plainly when you lose.
7. **Touching what is not yours, or lowering a bar to get green.** Thresholds, budgets, acceptance tests (`tests/acceptance_*` are overseer-owned and read-only), the ledger, shared packages without an ADR and a downstream re-run. Fix the cause or file `docs/proposals/`.
8. **Retyped evidence.** Paste terminal output unedited. `grep` every test or file name you cite. Announce nothing while CI is red.
9. **Synthetic data flowing into real-data outputs, and invented observations.** Never.
10. **Autonomy drift.** Over a long run, re-read this section and the tier checklist at the start of every tier. Declare "done" only after running the thing.
