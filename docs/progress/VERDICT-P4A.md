## Findings
1. **M5's verifier accepts everything that is not a numbered claim or one of five exact strings.** I appended each of these to a genuine rendered note and verified: "The tumour is growing rapidly in the liver.", "Metastasis confirmed.", "No need to worry.", "You do have cancer.", "Start chemotherapy immediately.", "Stop the current treatment.", "The patient is dying.", "This result is a lab error.", "The patient has liver involvement.", "Prognosis is poor.", "Surgery is recommended." — **all 11 accepted.** `FORBIDDEN_PHRASES` in `m5.py` are literally the five strings my v1 tests used (lower-cased), checked by substring; the rest is a regex check that numbers match their keyword-labelled sentence. A narrative safety verifier must accept only content warranted by the fact table (template-derivation), not blacklist what it was shown. My v1 tests were too weak (I tested exact strings) — I have added contract v2 (`tests/acceptance_p4/test_m5_contract_v2.py`): 17 unwarranted sentences must be rejected in three positions, and every genuine sentence must be accepted alone but rejected when one word is changed. A strict reference passes all 18; Gemini's `m5.py` fails all 18 (and still passes v1).
2. **E9 numbers presented as primary-verified are not supported.** `docs/evidence/E9.md` quotes "Full-Text Paper Table 2" (CA 15-3 CVi 6.1%, CVg 43.1%, II 0.14; CEA CVi 12.7%, CVg 55.4%, II 0.23). The paper (CCLM EuBIVAS tumour markers, PMID 33964202) is not open access (Europe PMC: not in PMC), the abstract does not contain these numbers, and `check_evidence.py` verifies only blockquotes, so unquoted numbers pass. I downgraded E9 to `SECONDARY`. M3 takes `cv_within` as an input, so the algorithm is unaffected, but the registry and docs claim "direct calibration" to these numbers.
3. **S7 headline is the model grading itself.** On the contract cohort the data are generated from M3's own model (AUROC 0.996, ECE 0.002); ML_PROGRAM §10 requires a logged triage for such numbers and a headline from the independent world. The `vigil-sim` result (AUROC error-vs-rest 0.859 [0.810, 0.901]) is the informative number, and only gross-error detection was evaluated there — **real-change detection on `vigil-sim` recurrences was not reported.**
4. **S2 operating point chosen on the evaluation cohort.** K2 α=0.15 and the 30 U/mL cutoff were picked from a sweep on the seed-42 evaluation cohort; the matching should be selected on the calibration cohort (seed 999) and then evaluated once.
5. **Smaller:** a `# reality: allow(R1)` was added to `run_vigil_sim_study` with an inline reason but no `docs/STUBS.md` entry (required by VERDICT-P3); PR text overstates M5 ("Provenance fact-grounding … rejection of swapped percentages") — true only for keyword-matching sentences.
