# Overseer verdict — Phase 7a treatment continuity & RT triage (PR #44) and conditions P11-A…P11-F (2026-10-17)

**Verdict: P11-A (lifecycle), P11-E (hashed tokens), P11-F ACCEPTED; P11-B accepted via ADR 0013 (see note). Phase 7a deliverables ACCEPTED WITH CONDITIONS: the scheduler itself is correct, but Study S8 does not evaluate it, the harm model overstates its evidence, and two integrity/consent defects (one of them a core consent bug present since Phase 5a) were fixed by the overseer. PR #44 merged; remaining items are conditions P12-A…P12-E.**

## What is genuinely good (verified by me)
- **CP-SAT scheduler is correct:** on 60 random small instances (1–2 machines, capacity 1–2, random downtime days, 2–5 patients, all four clinical contexts) its total harm equals exhaustive search in every case with zero capacity violations. Gemini's own "brute-force" test was a hand-built 2-patient case; mine is independent.
- **S8 reproduces exactly:** re-running `scripts/run_study_s8.py` gives identical results (same seed), and H2 is honestly reported as REFUTED.
- Bad-news lifecycle (request release → clinician unlock → re-lock) with a real-server Playwright test; caregiver tokens hashed (SHA-256) with preview-only listing; ADR 0013/0014; CI really green on four jobs; acceptance tests untouched; 12 attack checks pass.

## Defects (all reproduced by me)
1. **Study S8 does not evaluate the optimiser.** The simulated "HarmAware" arm is a greedy sort by marginal harm (`simulate_policy`, `eligible.sort(key=sort_key…)`); `RadiotherapyScheduler.solve` (CP-SAT) is never called in the study. PREREG-S8 and the PR text call that arm "Vigil M7 CP-SAT Solver", and "H3 fairness confirmed" measures disparity of a greedy policy that has no fairness constraint. The shipped optimiser has no policy-level validation. (RR2: validation must exercise the implementation.)
2. **The study's result is unflattering and under-reported:** the trivial static `UrgencyHeuristic` has *lower* mean harm (0.0177 vs 0.0185, CI excludes zero) than the harm-aware arm; the PR leads with the 12.7% gain over FCFS. Also `p_value_empirical` for H1 is 0.097 while the CI is reported "strictly positive" (the p-value is `mean(delta<=0)` on a different resampling than the CI) — report one method.
3. **Pre-registration cannot be shown to precede results:** one squashed commit contains PREREG, script and results; the PREREG also promised an arrival-rate sweep (λ 2.0–3.5) and a 3–10 day MTTR sweep; only three MTTR values were run, silently. The study never reaches a scarcity regime (mean wait ≈3.4 days; Nigeria's problem is weeks), so it does not test the situation M7 exists for.
4. **Harm-model evidence is inflated.** `EVIDENCE.md` lists E8 as `SECONDARY` and says the primary text is still to be retrieved; the model labels the lumpectomy context `HIGH` and cites "Mackillop et al., Clin Oncol 2016, n=79,600" as if retrieved. Grace period (56 d), ramp (84 d), base event rates and interruption penalties have no source at all. The three "ASSUMPTION" contexts carry made-up "95% CI" ranges (e.g. 1.03–1.18) that look like statistics. (Evidence discipline: a number in code needs a retrieved source or an explicit assumption range.)
5. **`POST /continuity/schedule/confirm` trusted the client (fixed by overseer):** a clinician could write ledger entries for another patient (including one without consent), nonexistent machines, negative delays, 999 "marginal harm", duplicates; unknown courses returned "success" with 0 entries. The "immutable" ledger was forgeable.
6. **Consent ignored by listings (fixed by overseer):** `GET /courses` and `/ledger` showed patient IDs, cancer context and delays to nurses/quality leads regardless of consent.
7. **Consent withdrawal never worked over HTTP (core bug, fixed by overseer).** `verify_patient_consent` skipped non-granted records and kept scanning, so an older "granted" record stayed active: posting `granted=false` or `withdrawn_at` left the patient fully readable. Every earlier "withdrawn → 403" test edited the database directly, so none caught it. All consent-related claims in Phases 5–7 must be re-tested over HTTP.
8. **Retyped evidence again.** The "byte-for-byte" `gh pr checks` block in the reply is not gh output (header text and truncated names); the statuses were correct (I checked). Paste with a code block from the terminal, no editing.
9. **Smaller:** solve builds `course_map[c.patient_id]` (a second course for the same patient overwrites the first); solve includes patients regardless of consent without telling the clinician; Lighthouse CI relaxed to Perf ≥ 75 / TTI ≤ 4500 ms (ADR 0013 — acceptable as documented, report both).

## Overseer fixes (done directly in PR `fix/continuity-consent-and-ledger-integrity`)
Latest-record-wins consent evaluation (`consent.py`); consent-filtered `/courses` and `/ledger`; atomic, server-derived `/schedule/confirm` (404 unknown course, 422 wrong patient / unknown machine / duplicate, delay and harm recomputed server-side, consent verified per patient); `tests/acceptance_p12` (3 tests, all fail on PR #44, pass with the fix; 104 tests green across P5/P7/P8/P9/P11/P12, API and contract suites).

## Conditions
- **P12-A** Rework S8: policy arms call the real `RadiotherapyScheduler` in a rolling-horizon loop (greedy proxies may stay as extra baselines, labelled); pre-register in its own commit *before* the run (show `git log`); run the arrival/MTTR sweeps promised, including a scarcity regime (utilisation ≥ 90%, waits of weeks); one CI method; report that the urgency heuristic beats the optimiser if it still does, and investigate why (objective vs. realised harm). Retract the "CP-SAT" label for results that did not use it. Rename the study (ML_PROGRAM S8 is the K7 causal study).
- **P12-B** Harm model evidence: retrieve E8's primary source and pass `audit_excerpts`, or downgrade the label to SECONDARY; mark grace/ramp/base rates/penalties ASSUMPTION with explicit ranges; replace invented CIs on assumptions by labelled assumption ranges; sensitivity analysis over *those* parameters; show the optimiser's ranking stability across the range.
- **P12-C** Fix `course_map` collision; decide and document (ADR) whether solve may include patients without consent (treatment-relationship basis) and show excluded/included counts in the response.
- **P12-D** Re-test, over HTTP, every consent-withdrawal / expiry claim made in Phases 5–7 reports; list tests that edited the DB directly and replace them.
- **P12-E** Paste raw terminal output for `gh pr checks`.
