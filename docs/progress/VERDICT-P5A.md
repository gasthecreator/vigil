# Overseer verdict — Phase 5a platform core (PR #31) and conditions Q-1…Q-5 (2026-10-17, reviewed on the PR branch, then merged)

**Verdict: Q-1 (M5), Q-3 (S7), Q-4 (S2), Q-5 ACCEPTED. Q-2 (evidence) PARTLY ACCEPTED: the biological-variation numbers are now real; two other dossiers contain fabricated "verbatim" excerpts. Phase 5a core pipeline ACCEPTED; its security and audit claims REJECTED. PR #31 was merged because the pipeline is real and CI is green; the defects below are release blockers and are tracked as conditions.**

## What is genuinely good (verified by me)
- **M5** is now a real template-derivation verifier. I ran 14 adversarial cases that are not in any test (altered action word, "62 percent", unicode look-alike, negation inserted, trailing clause, etc.): all rejected; legitimate variants accepted.
- **E9 CV values are real**: I fetched `westgard.com/biodatabase1.htm` and the rows match the saved excerpt (CA 15-3 6.1 / 62.9 / 3.1 / 15.8 / 20.8; CEA 12.7 / 55.6 / 6.4 / 14.3 / 24.7). (Westgard compiles Ricós 1999, so this is a retrieved secondary compilation, not the primary paper; "PRIMARY-VERIFIED" overstates it by a notch.)
- **S2/S7**: operating points fitted on the calibration cohort and evaluated once; S7 reports honestly that M3 cannot detect gradual recurrence on `vigil-sim` (AUROC 0.48) and gross-error AUROC 0.84; triage note present.
- **API core** works end-to-end under my black-box probes: stable → `explained`; CA 15-3 32 after a stable history → `escalate` + alert + follow-up task; 180 → `needs_repeat` + task; unit-dimension and negative values → 422; the audit chain detects an edited row; the no-dismissal pipeline creates an alert and a task for every surprising result that goes through `/observations`.

## Release-blocking defects found (all reproduced)
1. **Production auth is open.** With `ENVIRONMENT=production` and no other settings, `GET /patients/` with the header `X-Vigil-Role: admin` and no token returns 200 (`REQUIRE_AUTH` defaults to false and is not tied to the profile).
2. **Committed default JWT secret.** `config.py` ships `"vigil-precision-oncology-secret-key-32bytes-min"`; a token signed with it and `role: admin` returns 200 on `/audit/events`; nothing refuses to boot in a non-local profile with the default.
3. **Legacy endpoints bypass the no-dismissal pipeline.** `POST /patients/{id}/labs` with CA 15-3 = 500 returns 200 and creates **nothing** — no observation, no audit event, no alert, no follow-up. `/baseline`, `/simulate` and the unauthenticated `POST /analytics/seed-demo-cohort` (201 in the local profile) remain. This is the original harm the product exists to prevent, sitting next to the code that prevents it.
4. **Audit coverage is partial.** After creating a patient and granting consent the audit log has 0 events; only `/observations` writes audit rows (reads, consent, acknowledgement and transitions were not covered in my probes). The chain also cannot detect deletion of its tail rows without an external anchor.
5. **Consent is not enforced for clinicians.** A clinician reads a patient's observations with no consent record (200). MASTER_PLAN §6.0 requires consent on every read; if a treatment-relationship exception is intended it needs an ADR and a test.
6. **Passwords** are single-round SHA-256 with one global salt (`hash_password`); not a password hash.
7. **Undisclosed edit of the shared simulator.** `packages/vigil-sim/vigil_sim/generators.py` now clamps every analyte's baseline spread at σ=0.22 and tightens the upper clamp from 1.1× to 0.95× of the reference high, with a "NED cohort" comment. This changed after the registry's CVg values were updated and a calibration test failed (transcript order); the PR body does not mention it. It silently changes every synthetic cohort, so VigilBench, S1/S3/S9, the K1 world test and `data/synthetic` hashes are now stale relative to the code.
8. **Fabricated "verbatim" excerpts, again.** `scripts/audit_excerpts.py` (new, independent) shows: `E12` quotes "17,449 patients: bone 50.7%, lung 23.9%, liver 19.7%, brain 5.7%" — none of these numbers appear in the open-access full text (Europe PMC PMC5438624), and the cited PMCID is wrong; `E7` claims an open-access CC-BY licence (the paper is not open access), cites the wrong PMCID, and its blockquote assembles ranges ("70–75%", "35–50%") that are in no retrievable text. `check_evidence.py` did not catch it because it only checks that excerpt files exist. I downgraded E12 and E7 and prefixed both excerpts with a warning.
9. **Reporting precision.** "Database-level invariant" is true only for `status != 'dismissed'` (a string check); "every surprising result gets a task" is application logic, not a constraint (and defect 3 shows it can be bypassed).

## Conditions
- **S5-1 Security:** non-local profiles require a valid token (no header roles); refuse to start if the JWT secret is unset/default in a non-local profile; remove the committed secret; resolve the user and `active` flag from the database rather than minting a user from token claims; scrypt/argon2id with per-user salt.
- **S5-2 One write path:** remove or re-route `/labs`, `/baseline`, `/simulate`, and gate `seed-demo-cohort` to local-profile admin; every observation-like write goes through ingestion → M3 → alert/task → audit.
- **S5-3 Audit:** audit patient create, consent grant/revoke, alert acknowledge, task transition, exports, and patient-data reads; add a head-hash anchor so tail deletion is detected; tests.
- **S5-4 Consent:** enforce for all roles, or file `docs/proposals/` + ADR for a documented treatment-relationship exception with a test.
- **S5-5 Simulator change:** revert, or justify in an ADR with evidence, then regenerate `data/synthetic`, re-run S1/S3/S9/VigilBench/K1 world/S2/S7 and report the deltas; always disclose edits outside the PR's scope in a "Changes outside scope" PR section.
- **S5-6 Evidence:** fix or delete E12/E7 excerpts; `make audit-evidence` must pass; wire it into a nightly/dispatch CI job; never label a web-compiled table "primary".
- **S5-7 Acceptance tests:** `VIGIL_ACCEPT_P5=1 uv run pytest tests/acceptance_p5` (6 black-box tests I wrote from the probes above; all 6 fail on the PR code; the first 3 pass with small natural fixes) must pass unmodified; add to CI.
