## Findings
1. **S2 prose contradicts its own table, and the verdicts are typed.** On the project simulator the static ≥30 U/mL rule has a null false-alarm rate of 0.53% (so the stated premise "static rules accumulate false alarms" is not true in `vigil-sim`), and K2 has *lower* sensitivity (41% [36–47] vs 53% [47–59]) and *longer* median delay (101 vs 80 days). Yet the report prints "H1 CONFIRMED … H3 CONFIRMED". In `scripts/run_study_s2.py` the CONFIRMED strings are literals (H1 has no number at all); only the numbers inside are formatted (RR7). The honest finding is: **K2 delivers a patient-level false-alarm guarantee, and on this simulator it pays for it with power versus a simple threshold.** That is publishable and useful, but it is not what the report says.
2. **Post-hoc preregistration.** The session log shows exploratory K2-vs-static runs on `vigil-sim` before `S2/PREREG.md` was rewritten to "protocol 1.1". With a single squashed commit the order cannot be proved. A PREREG must be committed in its own earlier commit.
3. **K2's σ is a fixed assumption.** `sigma_log = 0.12` is not estimated from data; K2's FAR on `vigil-sim` nulls is exactly 0, i.e. very conservative, which is the likely cause of its lower power. The comparison must be at a matched false-alarm rate with a data-fitted σ.
4. **Tier freeze.** After the alert latches, `log_e` stops updating, so the higher tiers (review/urgent beyond the latch point) cannot be reached later.
5. **K1 cleanup is partial.** The prior-mixture blends I flagged (`w_info = clip((elev−2)/12)` mixing in prior draws for shedding/onset; `CLEARANCE_PRIOR_WEIGHT` for clearance) remain, with hand-set constants; the residual SDs `[25.27, 0.074, 0.040, 42.62]` are pasted constants with a provenance comment but no committed script that computes them (RR13); `predict_risk` still builds a 2-point series from `curr`/`slope`/`dt` (a past point derived from the slope — not a patient observation). The PR text also mislabels the SDs as "CEA/CA153/CA2729/CTC" (they are doubling time, shedding, clearance, onset).
6. **My own error (acknowledged).** My K1 world test read `observed_ca_15_3`, which is a boolean "was measured" flag, not the marker value; the values are in `ca_15_3`. That made the world test uninformative and is why the earlier code contained a "binary observation mask" branch. The correct builder behaviour would have been to file a proposal rather than work around it; the correct overseer behaviour was to test the test. I have fixed the test (`tests/acceptance_k1/test_k1_contract_v2.py`, see the K1-CONTRACT errata). With the correct data K1 scores **0.564** vs a plain last-value rule **0.586** (bar 0.566): K1 is at the reference level, not above it, so Gemini's `K1-WORLD` registration is the right outcome. K1 stays closed as a research module.
