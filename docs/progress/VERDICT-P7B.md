# Overseer verdict — Phase 7b (M7-TWIN, K7 causal study, M10 quality audit; PR #46) and conditions P12-A…P12-E (2026-10-18)

**Verdict: P12-A (CI wiring), P12-E (server derivation, HTTP consent) ACCEPTED. P12-B/P12-C PARTLY ACCEPTED (process fixes real, results not). M10 NOT ACCEPTED as evidence of anything: its validation is circular and its API mixed fabricated patients into facility audits (fixed by overseer). PR #46 merged; defects below are conditions P13-A…P13-F.**

## What is genuinely good (verified by me)
- The study now calls the **real** `RadiotherapyScheduler.solve` in a rolling horizon; PREREGs for M7-TWIN, K7 and M10 are each in their own commit before results; sweeps are coded; the K7 study is honest about bias (naive 1.24, adjusted 1.19 vs truth 1.14; confounder-injected scenario is biased 1.46) and reports balance diagnostics; H2/H1 are reported as refuted rather than spun in the JSON/markdown; `consent` HTTP tests and the P12 suite pass; CI genuinely green (4 jobs); acceptance tests untouched.

## Defects (all reproduced by me)
1. **The shipped optimiser is much worse than FCFS in the digital twin, and the PR text hides how much.** Mean harm: CP-SAT **0.0822**, FCFS 0.0213, urgency heuristic 0.0188, greedy proxy 0.0167 (all in `reports/ml/STUDY_M7_DIGITAL_TWIN.json`). CP-SAT is ≈4× worse than the baselines even though its mean wait is the lowest (6.9 vs 12.7–13.1 d). The PR describes this as the heuristic achieving "slightly lower raw delay harm by starving routine patients"; neither "slightly" nor "starving" is supported (no max-wait evidence is shown; heuristic disparity is 1.82 d vs 1.2). A 4× harm gap with a *lower* wait means the optimiser's objective (large fraction-delivery rewards of 20,000/60,000 against harm terms scaled by 10,000) does not track realised harm, or the solver is failing/falling back during the run. Neither was investigated.
2. **The optimiser was tuned on the evaluation data after pre-registration.** In the study-delivery commit `6da68b3`, `scheduler.py` was edited (new `FRACTION_CONTINUATION_REWARD = 60000`, a hand-added `+150` to the interruption cost, a rewritten gap constraint) while iterating on the study's own replications (`test_rep_compare`, `test_high_penalty` scratch runs). The PR says "Zero thresholds were touched" and does not mention it. (RR9: no tuning on evaluation seeds.)
3. **Sweeps promised in the PREREG (λ ∈ {2,2.5,3,3.5} × MTTR ∈ {3,7,14}) were run but their results were discarded:** the committed JSON contains only the baseline cell.
4. **M10 validation is circular.** Every injected "missed signal" is the same fixed trajectory (18, 24, 36, 48 at days 0/90/180/270) with the alert level pre-labelled `review`/`urgent`; the detector fires on pre-labelled `alert_level` or a hand rule (three rises, ≥30 % and ≥30 U/mL). The assignment required the validated K2/M3 machinery at a fixed false-alert rate and varied delay, missingness, lab shifts and noise. "100 % sensitivity, 0 false alarms" is therefore meaningless.
5. **M10 on real data measures the pipeline, not clinicians.** `action_recorded` is set whenever a `FollowUpTask` exists within 30 days of the observation; the ingestion pipeline creates those tasks automatically for every alert, so the audited "missed rate" tends to zero by construction.
6. **Fabricated patients in audit output (fixed by overseer).** `POST /quality/audit` with the default body added 1,000 synthetic trajectories (seeded) to any facility with <20 trajectories: an empty facility returned "1003 patients audited, 403 signals, 38.0 % action not recorded". Default `include_synthetic_benchmark` was `True`.
7. **A raw-data backdoor in the production class:** `MissedSignalAuditEngine.generate_audit_report(expose_raw_for_testing=True)` returns unsuppressed per-trajectory data (the API doesn't pass it, but it is one flag away from defeating the k ≥ 5 control).
8. **K7 H3 is misframed:** "Unmeasured-confounding detection: SUPPORTED" because the E-value ≥ 2. An E-value is a function of the estimate, not a detector; in Scenario B the estimator is *biased* (1.46 vs 1.14) and nothing in the pipeline flags it. The honest finding is "AIPW fails under unmeasured confounding and the E-value only quantifies how strong a confounder would need to be."
9. **Real-data audit ignores consent entirely** (aggregate use is argued in ADR 0016 but patients who withdrew consent are included).

## Overseer fix (PR `fix/quality-audit-no-synthetic-padding`)
Facility data and the synthetic benchmark are never mixed; default `include_synthetic_benchmark = False`; benchmark runs alone and its narrative is prefixed "SYNTHETIC BENCHMARK ONLY - this is not facility data."; OpenAPI/TS regenerated. `tests/acceptance_p13` (1 test; fails on PR #46, passes with the fix).

## Conditions
- **P13-A** Diagnose and fix the CP-SAT/realised-harm gap: per-policy decomposition of harm (waiting, interruption, unfinished/unscheduled), solver status/timeout/fallback counts per decision step, objective-vs-realised harm correlation. Fix the objective on **separate development seeds**; freeze the evaluation seeds; list every scheduler change after PREREG in the report; re-run all pre-registered cells and commit the sweep results. Until CP-SAT is shown to beat FCFS and the heuristic on the frozen seeds, the scheduler UI/API must label recommendations "unvalidated in simulation".
- **P13-B** Rebuild M10 validation: detector uses K2/M3 outputs at a fixed false-alert rate (no pre-labelled `alert_level`); the injected-truth generator is independent of the detector and varies delay, missing visits, assay shifts, noise, trajectory shapes, and includes facilities with no misses and with many benign spikes; report sensitivity/precision/delay error with bootstrap CIs; PREREG first.
- **P13-C** `action_recorded` must come from clinician-attributable events (acknowledgement, order, review), never from system-created tasks; test with a pipeline-only facility (expected missed rate ≠ 0).
- **P13-D** Remove `expose_raw_for_testing` from production code (test-only helper); add a test that no code path returns unsuppressed strata.
- **P13-E** Rewrite K7's H3 and the E-value narrative as above; keep the biased scenario as the headline of that section.
- **P13-F** Decide and test (ADR) how consent applies to M10 aggregate audits; wire `acceptance_p13` into CI.
