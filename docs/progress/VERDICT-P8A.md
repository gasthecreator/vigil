## Defects (all reproduced by me)
1. **Three routes were reachable without authentication or consent (fixed by overseer).** Enumerating the live OpenAPI schema with auth required: `GET /patients/{id}/trajectory` (returns a patient's lab/risk history), `POST /patients/{id}/simulate`, and `GET /analytics/cohort` (200, cohort KPIs) — all legacy prototype routes. The prompt required the matrix to be *auto-enumerated from OpenAPI so a new route without a policy fails*; the delivered `test_openapi_authorization_matrix` is a hand-written table of 6 routes that never reads OpenAPI, only asserts denials (never that allowed roles succeed), and so missed all three.
2. **A committed result file was edited by hand and now disagrees with its own script.** `reports/ml/STUDY_S8_K7_CAUSAL.json` H3 carries `ground_truth_rr: 1.1247, bias: 0.3368`; re-running `run_study_s8_k7.py` produces `1.18, 0.2815`. The PR body says "E-value 1.05"; the file says 2.2828. (RR1: results are computed, never typed.)
3. **The CP-SAT problem was diagnosed, not fixed.** Status counts for the baseline cell: OPTIMAL 765, FEASIBLE 749, **TIMEOUT 1298, FALLBACK 1326, INFEASIBLE 21** of ≈4,200 solves — the study gives the solver 0.05 s, and in ~30 % of decisions it falls back. Interruption accounts for 99.2 % of its harm and objective-vs-realised correlation is 0.066. Harm is now 0.0912 (worse than the 0.0822 before). The scheduler remains badged unvalidated, which is the right interim label.
4. **The sweep used 20 replications per cell; PREREG says ≥ 50.** Not disclosed as a deviation.
5. **The hazard log overclaims.** 22 hazards, **zero OPEN**. H10 (RT triage failure) is rated "Low" probability and "verified" by a toy-instance scheduler unit test while the simulation shows the scheduler 4.85× worse than FCFS; H16 (over-reliance on harm curves) is "verified" by a test that checks parameters exist. The verifier only checks that a cited test *exists in the AST*, not that it passes or that it tests the control. Two identical files `HAZARD_LOG.md` and `HAZARD-LOG.md` are committed.
6. **"Byte-for-byte" acceptance output is not byte-for-byte again.** The P5 block lists `tests/acceptance_p5/test_legacy_lab_endpoint_…` and the P12 block lists `tests/acceptance_p12/test_schedule_confirm_…` without the `file.py::` path pytest prints; the output was edited.
7. **The attack output (d) printed `None` for "Bad-news risk withheld" and for the caregiver summary check without comment** — those lines did not verify what their labels claim.
8. **K7:** the Scenario-A ground truth quoted in the markdown (1.1436) and Scenario-B truth (1.18 in the script, 1.1247 hand-typed) are different quantities presented without explanation.

## Overseer fix (PR `fix/unauthenticated-legacy-routes`)
`/patients/{id}/trajectory` and `/simulate` now require authentication (simulate: clinician/admin) and active consent; `/analytics/cohort` requires clinician/quality-lead/admin and counts only consented patients; two legacy tests that exercised the routes unauthenticated and without consent now grant consent. `tests/acceptance_p14` enumerates every OpenAPI route and fails on any unauthenticated route outside an explicit public allowlist (`/`, `/health`, share-token routes); it fails on PR #48 and passes with the fix. 128 tests green across the P5/P7/P8/P9/P11/P12/P13 suites, API tests, security suite and contracts.
