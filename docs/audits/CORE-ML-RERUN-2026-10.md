# Core ML quality rerun — 2026-10

## Scope and evidence boundary

This pass follows `docs/MASTER_PLAN.md`, `docs/ML_PROGRAM.md`, the phase prompts under `docs/prompts/`, and the binding simulator/evaluation contracts. It focuses on synthetic cohort generation, landmark labels, feature handling, baseline fitting, leakage checks, survival metrics, and the K1/K3 engine paths. There is no real clinical longitudinal cohort in the repository, so this work cannot retrain or optimize a clinically valid model. The new experiment is synthetic research only.

## Remediated in this branch

- Landmark labels now distinguish recurrence, competing events, and early censoring. Unknown outcomes remain missing and learned classifiers require explicit IPCW weights.
- Simulator population assumptions are moved from code literals into versioned profiles. The balanced profile is explicitly synthetic and is not a country-population estimate.
- Unavailable measurements and derived features remain missing, with availability indicators. B3, B4, and the fast landmark logistic baseline fit median imputers on training data only.
- The shuffled-label canary now fits imputation within each cross-validation training fold, preventing held-out feature distributions from informing preprocessing.
- IPCW AUC evaluation uses a sorted weighted concordance calculation. Undefined AUC/Brier results return NaN instead of plausible-looking chance/zero scores.
- The former K3 Bayesian sampler and its posterior-shaped outputs were removed; `BayesianJointModelK3` now fails closed. The logistic research baseline has an explicit canonical name and no unsupported horizon argument; the old constructor remains as a source-compatibility wrapper.
- `ProductionEnsembleK8` now fails closed because its fixed weighted formulas never called the named models.

## Unresolved model validity findings

### K3 Bayesian joint model is not the registered model

Source inspection before ADR-0049 found that `BayesianJointModelK3` used fixed marker centering, priors and hazard constants, and a row-level trend sampler without patient random effects, competing-risk likelihood, or the registered shared-parameter structure. Its fast sibling was a logistic classifier, not a joint approximation. ADR-0049 removed the invalid sampler and makes fit, posterior checks, and prediction fail closed; the fast path is now `LandmarkLogisticResearchBaseline`, with `FastLandmarkJointModel` retained only as a legacy constructor wrapper. No valid K3 implementation exists. The registered replacement and preregistered evidence remain open under package E.

### K1 route and training validity remain open

The earlier competing `kinetic_k1.py` implementation has already been replaced by a compatibility shim to `k1.py`; the duplicate public inference path is no longer present. The canonical source still has unresolved research assumptions: a fixed seven-visit schedule, uniform parameter bounds, fixed synthetic marker/noise settings, simplified one-marker training data, and particle-filter jitter. K1 recurrence-risk prediction fails closed. These paths do not establish a simulator-aligned or clinically valid K1 model; see the current route and artifact findings in `CORE-ML-AUDIT-2026-10.md` and `PROP-K1-EVENT-SEMANTICS.md`. Do not tune or claim K1 performance outside a preregistered study.

## Calibration evaluator mask defect (Q-7 B)

The legacy calibration evaluator read synthetic CA 15-3 values without checking whether the assay was measured. It could therefore count hidden values as detections and specificity observations. The evaluator now uses only `observed_mask=true` values, includes all cohort patients in coverage denominators, reports measurement coverage, and returns undefined specificity when no measured control assays exist. Regressions force hidden values high and remove every observation row for a recurrent patient. The existing G1 calibration test fails its unchanged single-seed conditional lead-time SD ceiling: 113.6151 days versus 110. Proposal `PROP-CORE-ML-MEASURED-CALIBRATION-GATE.md` records why this one-seed legacy gate needs overseer disposition and a pre-registered, mask-aware multi-seed estimand. No threshold or generator parameter was changed to fit the gate. Calibration evidence and the M13 simulator requirement remain open.

## Verification-bias estimator audit (Q-7 B/F)

Source review of `packages/vigil-eval/vigil_eval/verification_bias.py` found that no-verified/one-class cases returned plausible zero or 0.5 metrics; a NaN verification indicator cast to boolean became `True`; IPW propensities were silently clipped at fixed 0.05/0.95 bounds; and `evaluate_latent_class_em` initialized unverified outcomes from a fixed prevalence then iterated a classifier on its own pseudo-labels. That procedure did not implement an identifiable latent-class likelihood. Current source rejects unknown verification masks, requires verified binary labels and finite aligned features, returns NaN for undefined metrics, removes undocumented weight clipping, exposes propensity/effective-sample-size diagnostics, and disables the misleading pseudo-EM routine. Focused verification-bias, partner-analysis, and retracted-runner tests pass (34 total); Ruff passes on changed source and tests, and mypy passes on the changed evaluator module. This only hardens estimator semantics. The partner analysis' in-cohort propensity fit still has no preregistered validation, its exchangeability and positivity assumptions are not tested, and it cannot identify MNAR outcomes without extra assumptions or validation data. No verification-bias estimate from these methods is current model-selection or clinical evidence.

The S3 and aggregate benchmark entry points already fail closed, and the committed S3 report/retraction preserve the invalid study as historical only. Source review found unreachable legacy renderer code still hardcodes old S3 estimates and unsupported AUC-range claims; its text has been corrected so those claims cannot be revived if the fail-closed guard is removed. The historical report and JSON remain unchanged. A replacement S3 run requires a registered protocol and validation of the propensity assumptions before data access.

The shared feature extractor and simulator label helper returned a generic `recurrence_within_H` target name even though one produces observed-diagnosis labels and the other can switch between observed and oracle truth. The simulator helper also silently defaulted to observed diagnosis. Both paths now name/tag the target with the estimand and horizon; the simulator path marks its labels synthetic and requires callers to choose observed diagnosis or oracle truth explicitly. Regression checks assert metadata on both routes and reject omitted choices. No label values or frozen study outputs changed. This improves traceability, but does not identify latent recurrence under partial verification or validate the observed-label model.

## Additional simulator-profile finding (Q-7 B)

The active baseline profile `balanced_synthetic_v1` did not declare its facility, verification, or measurement-missingness assumptions; EXP-CORE-ML-008's profile hash therefore does not describe its complete synthetic data-generating assumptions. Preserve those results as historical, not current selection evidence. `balanced_synthetic_core_v3` now declares major G1/G2/G3 mechanisms alongside facility, verification, measurement-missingness, symptom, visit, and financial-friction assumptions; v3 validates required settings and consumes the declared values.
