## Repeated failure modes confirmed by the prompt history

The prompts and independent verdicts record a repeated chain of defects, not isolated wording issues:

1. **Computation represented by constants or prose:** hard-coded lead-time/latency, formula-generated training losses, typed verdicts, literal study results, hand-built model scores, proxy components presented as the named component.
2. **Invalid target or information boundary:** circular `is_anomaly`; latent truth exported as an unmeasured assay; censoring and competing events treated as negatives; oracle outcomes used as observed outcomes; repeated landmarks treated as independent; K1's private world mistaken for the product simulator.
3. **Evaluation contamination:** thresholds/operating points selected on test outputs; fixed acceptance assertions tuned on test seeds; post-registration code/objective changes; test data reused to resolve implementation choices; model and generator validating each other's assumptions.
4. **Claim and lineage mismatch:** route aliases named as distinct inference methods; stale reports/cards and result tables; incorrect producer attribution; a model registry mistaken for a complete inventory; CI/tests or security properties claimed without exercising the actual route.
5. **Safety failures in reachable product paths:** quarantined metadata without enforcement; random or hand-coded outputs behind production-sounding names; synthetic missing values substituted at inference; low scores rendered as reassurance; safety gates implemented only in UI or a sibling endpoint.

Q-7 therefore treats a prompt/report assertion as a hypothesis until traced to source, producer, committed result, exact test, route and claim surface. The runtime repair recorded in ADR-0037 is one completed root-cause fix from this trace; the API heuristic, K1/K3, historical study reconciliation, other model families, and end-to-end reproduction remain open.
