# EXP-K4-001 (study S4): deep irregular-time models, self-supervised pre-training and scale

**Status:** PRE-REGISTERED. This file is committed **alone**, before any K4 model code, any pre-training code and any run of any K4 model. Everything below is fixed at that commit; any later change is an *amendment* appended at the end with its reason. The only things looked at before writing it were the shape of the simulator output (visits per patient, which columns exist) and the existing code; no model result of any kind was seen.

**Authority:** `docs/ML_PROGRAM.md` §3.4 (K4) and study S4 (§6: "does pre-training help, and does scale help? If not, no pre-training in production"), `docs/MASTER_PLAN.md` §8.2 to §8.5 (protocol) and §13 (elimination protocol). **Data: synthetic only.** Nothing here is evidence about real patients.

## 1. Why this replaces the earlier S4
The earlier S4 (`reports/ml/RETRACTED/S4_PRETRAINING_SCALING/`) returned literal AUC lists, and `DeepZooK4.fit` learned nothing; its `predict_risk` is a hand-written formula that `scripts/run_benchmarks.py` (study S9) still scores under the name `K4_DeepZoo`. The committed K4 model card quotes those literals. All of that is retracted by the commit set that follows this file. This study trains real networks.

## 2. Questions
1. **Zoo.** Under one protocol, how do six irregular-time families (GRU-D, GRU-ODE-Bayes, Neural CDE, a continuous-time transformer, GRUwE, an irregular-time state-space model) compare with each other and with the strongest classical baseline, as the number of labelled patients grows (N = 50, 100, 200, 500, 1000)?
2. **Pre-training (S4a).** Does masked-analyte pre-training on unlabelled, domain-randomised simulator sequences improve performance when labels are scarce?
3. **Scale (S4b).** Does a larger network (small, medium, large) help?

## 3. Data (all from `vigil_sim`, G1 to G3, no `latent_*` or `observed_*` column is ever read)
- **Replication** `r` has base seed `s_r`. Development replications: `r ∈ {0,1,2}`, `s_r = 700 + 100 r`. Frozen replications: `r ∈ {0..9}`, `s_r = 20261201 + 100 r`. Seeds inside a replication: labelled pool `s_r` (G1, 1,000 patients, 730 days, `generate_cohort`), test cohorts `s_r+1` (G1, 500), `s_r+2` (G2, 500), `s_r+3` (G3, 500); unlabelled corpus sources `s_r+4` (G1), `s_r+5` (G2), `s_r+6` (G3), 3,000 patients each; domain-randomiser seed `s_r+7`; network initialisation seeds `s_r + 10 + k`.
- **Labelled training set of size N:** the first N patients of the pool (nested sets). Landmark rows are those of `WindowedFeatureExtractor.transform_cohort(..., horizon_days=365)`: one row per eligible visit, label = observed recurrence within 365 days, with follow-up time and event indicator for IPCW. Test cohorts use the same row definition.
- **Sequence input (deep models only):** the ten tracked analytes (`ca_15_3, cea, alt, ast, alp, ggt, total_bilirubin, calcium, creatinine, wbc`), each as `clip(log(value / reference_midpoint), -5, 5)` with the reference midpoint from `vigil_core.analytes.ANALYTE_REGISTRY` (a fixed constant, never fitted), a 0/1 observed mask per analyte, time since baseline / 365, time since the previous visit / 90 (clipped to [0, 10]), and eight static values (age, ER, PR, HER2, stage III or IV, three subtype indicators; the same information the classical baselines receive). Sequences keep the last 24 visits. The prediction for a landmark row is read from the model state at that visit, so a prediction never sees a later visit (tested).
- **Unlabelled pre-training corpora (no label is ever used):** (a) `PT-all`: G1, G2 and G3 cohorts; (b) `PT-offgen`: G2 and G3 only (no G1 sequence ever); (c) `PT-shuffled`: the `PT-all` corpus with the values of every analyte permuted across all (patient, visit) cells, keeping masks and times (a control that keeps the optimisation but destroys the biology). **Domain randomisation** (applied to the corpus only, never to labelled or test data), per patient: time axis scaled by a factor drawn log-uniform on [0.6, 1.6]; each visit dropped with probability drawn per cohort from U(0, 0.35) (at least two visits kept); log-scale noise with a standard deviation drawn per cohort from U(0, 0.25); a proportional laboratory offset `exp(beta)` with `beta ~ N(0, tau_c)`, `tau_c ~ U(0, 0.25)` per patient; an extra analyte-missingness probability per cohort from U(0, 0.3).

## 4. Models (all forward-only; all trained with the same loop)
Families (`vigil_ml/k4.py`, written after this file): **GRU-D** (decayed hidden state and imputations, Che et al.), **GRU-ODE-Bayes** (hidden state follows the GRU-ODE between visits, fixed-step RK4 with 4 sub-steps, GRU update at each visit; the deterministic encoder only, without the observation-likelihood and KL terms), **Neural CDE** (linear interpolation of the forward-filled path with time and an observation-count channel; Euler steps, 4 per interval), **continuous-time transformer** (causal attention with a learnable per-head exponential time-distance bias, 2 layers), **GRUwE** (E24: learnable exponential decay of the state, then a masked GRU update), **irregular-time state-space model** (diagonal, input-dependent step scaled by the elapsed time, Mamba-style selectivity, a sequential scan). **Not built: TabPFN-style prior-fitted networks** (they need a prior-fitted pre-trained network and a synthetic tabular prior that this repository does not have; stated as not built, not approximated). **Not built:** the contrastive pre-training objective, the adjoint and log-signature options of Neural CDE, and the GRU-ODE-Bayes variational observation model.
Sizes: hidden width 16 (small), 32 (medium), 64 (large) for every family (the transformer uses 2, 4 and 4 heads).
Head: a two-layer MLP from the state to one logit; probability = sigmoid. Parameter counts, state size, single-patient CPU latency (median and 95th percentile of 200 forward passes, one thread, 8 visits) and training wall time are reported per family and size (machine-dependent, labelled so).

**Classical baselines** (trained on the same N patients' landmark rows, no early stopping, the hyper-parameters of `scripts/run_benchmarks.py` study S1): B1 single threshold, B2 velocity, B3 regularised hazard (C = 1), B4 gradient boosting (depth 3, 100 trees), K3 fast landmark joint model.

**Training (identical for every family and arm).** AdamW, weight decay 1e-4, batch 32 patients, gradient clipping 1.0, binary cross-entropy over the landmark rows of the batch, at most 120 epochs. For a labelled set of size N the loop first trains on 80 percent of the patients (at least 10 held out) with early stopping on the held-out binary cross-entropy (patience 12), takes the best epoch count `E*`, then **retrains from the same initialisation on all N patients for `E*` epochs** and evaluates that model. Learning rate: chosen on the development replications only (section 7). Pre-trained arms initialise the encoder from the pre-training checkpoint and fine-tune all weights.
**Pre-training.** Masked-analyte modelling: each observed (visit, analyte) value is hidden from the input with probability 0.25 (value and mask set to 0) and the model predicts it, from the state at that visit (so from the history and the other analytes at that visit), with a linear head and a Huber loss; 25 epochs, batch 64, learning rate 2e-3, no early stopping; 10 percent of corpus patients held out to report the masked loss. Same recipe for every family, size and corpus.

## 5. Endpoints
- **Primary metric:** IPCW time-dependent ROC-AUC at 365 days on the G1 test cohort (`vigil_eval.ipcw_time_dependent_roc_auc`, as in studies S1 and S9). Secondary: IPCW Brier, expected calibration error (10 bins), the same on the G2 and G3 test cohorts (models are trained on G1 labels only; these are cross-generator tests), latency, parameters.
- **Arms and sizes run in each frozen replication:**
  - **Zoo:** all six families, medium, scratch, all five N.
  - **Reduced subset for the pre-training and scale studies (a compute decision made here):** `F3 = {GRU-D, continuous-time transformer, state-space model}`. For `F3`, medium: scratch, `PT-all`, `PT-offgen`, `PT-shuffled` at all five N. Scale: sizes small and large, scratch and `PT-all`, N ∈ {100, 1000} (medium comes from the previous line).
  - **Control (leakage canary):** GRU-D, medium, N = 1000, trained on labels randomly permuted among training patients (seeded), evaluated on true test labels. If the mean canary AUC over replications is outside [0.45, 0.55], every result of the study is declared void and reported as such.
  - Classical baselines at all five N.

## 6. Hypotheses and decision rules
Uncertainty: paired bootstrap over the replications (B = 2,000, RNG seed 20261201); all statistics are means over replications of a within-replication quantity. The **primary family** is {H1, H2, H3}; intervals for it are percentile intervals at level `1 − 0.05/3` (Bonferroni). Everything else is descriptive with 95 percent intervals and supports no claim. A "material" difference is 0.01 AUC, except in H3 where the minimum effect is 0.005.
- **H1 (pre-training helps when labels are scarce).** `Δ1` = mean over replications and the three families of `AUC(PT-all) − AUC(scratch)` at N = 100, medium. Met if the lower bound of `Δ1` is > 0.01.
- **H2 (a deep model beats every classical baseline when labels are plentiful).** The **designated family** is the family with the highest mean development AUC at N = 1,000 (scratch, medium), fixed by the development run (section 7). `Δ2,b` = mean over replications of `AUC(designated, scratch, medium, N = 1000) − AUC(baseline b, N = 1000)` for each of the five baselines. Met only if **every** `Δ2,b` has a lower bound > 0 (intersection-union rule; the strongest baseline decides).
- **H3 (scale helps).** `Δ3` = mean over replications and the three families of `AUC(large, scratch) − AUC(medium, scratch)` at N = 1,000. Outcome classes: **scale helps** if the lower bound > 0.005; **scale does not help** if the upper bound < 0.005; otherwise **inconclusive**. Also reported: small versus medium.
- **Descriptive:** `PT-offgen` and `PT-shuffled` against scratch and against `PT-all` at every N; the label-efficiency curves; the smallest N at which each deep family (scratch) reaches the strongest baseline's AUC; cross-generator AUC; ranking of the six families; the pre-training masked loss at the first and last epoch.
**Kill and fallback (from `docs/ML_PROGRAM.md` study S4):** if H1 is not met, **no pre-training is claimed or shipped** (no pre-trained checkpoint is exported or registered). If H2 is not met, K4 is **not claimed to beat classical models**; it stays a research module outside every production ensemble. If H3 says scale does not help or is inconclusive, medium is the largest size anyone is told to use. A pre-registered failure is an acceptable outcome (§13); the elimination record is `experiments/EXP-K4-001/CONCLUSION.md`.

## 7. Development, selection, and the single frozen run (no tuning on evaluation data)
- Development replications run the whole design (`run.py --dev`) for debugging and for exactly two selections, both written by the script into `hyperparameters.json` and committed before the frozen run: (i) the **learning rate** per (family, scratch or pre-trained): scratch from {1e-3, 3e-3}, fine-tuning from {3e-4, 1e-3}, by the higher mean development AUC (G1 test) averaged over N = 100 and N = 1,000, medium; ties go to the smaller rate; (ii) the **designated family** for H2. Nothing else is selected on any data; epochs are chosen inside each fit by the held-out split of its own training set.
- The frozen run (`run.py --frozen`, replications 0 to 9) is executed **once**. If code changes afterwards the old result stays committed and an amendment and a new run are added. The epoch limits, patience, sizes, masking rate, corpus sizes and all thresholds above are fixed here and are not changed after seeing any result.
- Every number in the report is written by `experiments/EXP-K4-001/run.py`; none is typed.

## 8. Invariants tested before the frozen run (`packages/vigil-ml/tests/test_k4.py`)
1. Causality: changing any visit after step j changes no output at steps up to j, for every family.
2. Padding invariance: appending padded steps changes no output at real steps.
3. Mask semantics: the value stored under a mask of 0 has no influence on any output.
4. Every family learns a planted signal (a label that depends on the last observed value of one analyte and on the gap since the previous visit) to AUC > 0.9 on held-out sequences, and fails to (AUC < 0.6) when the labels are shuffled.
5. Pre-training lowers the masked loss on held-out sequences compared with the untrained model, for every family.
6. Safetensors round trip reproduces the outputs exactly; ONNX export of every family reproduces the torch outputs within 1e-4 on probabilities; no pickle is used anywhere in the module (source scan).
7. The module and the study script never read a `latent_*` or `observed_*` column (source scan); the model receives arrays only.
8. Fitting is deterministic for a fixed seed.

## 9. What will be reported regardless of outcome
All five N for every family, arm and size; the strongest baseline first at every N; H1 to H3 as passed or failed with numbers from `results.json`; the descriptive tables; the canary; latency, parameters and training time; the development file and `hyperparameters.json`; every export or parity failure. If H1, H2 or H3 fails, `CONCLUSION.md` is the elimination record. The §13.2 requirement of three serious attempts is addressed in `CONCLUSION.md`; "infeasible" is not written unless it is met.

## 10. Not in scope
Real data of any kind, including MIMIC-IV lab series (access is a human action) and public longitudinal lab corpora; the contrastive objective; TabPFN-style models; a hyper-parameter search beyond the learning-rate grid; ensembling; calibration or conformal wrappers on K4 (K8's job); multi-analyte forecasting as a task.
